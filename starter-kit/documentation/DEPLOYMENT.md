# Build and Deployment Runbook

## Intended workflow
1. Confirm product config and media are complete and approved.
2. Run checks (types, tests, build) with real scripts once the project exists.
3. Vite builds static assets with `base: './'` so relative paths work under a subdirectory.
4. Build transform converts `dist/index.html` to **`dist/index.php`** and inserts the **company-approved, syntax-checked PHP head snippet**.
5. ZIP **the contents** of `dist` at archive root, not a wrapper `dist/` folder.
6. The company uploads/extracts into the chosen PHP-capable hosting directory.
7. Open the published URL and execute QA checklist before launch.

## Example target ZIP
```text
flexfind-pro.zip
  index.php
  assets/
    index-[hash].js
    index-[hash].css
  images/  (if public images are included)
  videos/  (if supplied and bundled)
```
The actual filenames may vary; assets generated by Vite must be preserved. `npm run package` builds assets, prepares `index.php`, and writes `artifacts/<product-slug>.zip`. It intentionally fails until the approved tracking template and non-placeholder product configuration are present. See `PACKAGING.md`.

## cPanel-specific checks
- Deploy to intended subfolder, such as `public_html/flexfind-pro/`.
- Host recognizes and executes `index.php` as directory index.
- Server contains readable `includes/store-tracking.php` within the parent-path search range.
- Rendered HTML contains the tracking script once, not `dead_store_tracking`.
- JS/CSS/media URLs return 200; no console errors and no blank root.
- Confirm `index.php` is not being served as raw source or downloaded.
- Verify ERP access and browser CORS from the **actual** deployed origin.
- Test full URL with UTMs and `fbclid` (can be dummy parameters, not fake orders).
- Verify order tests only with authorized staging/test identifiers or company approval for live.

## Packaging guardrails
- Fail packaging if required config, `index.php`, manifest/JS/CSS, or tracking snippet is missing.
- No `node_modules`, source TSX, `.env`, private tokens or credentials in ZIP.
- Validate relative asset paths and PHP syntax (if PHP CLI installed).
- Avoid renaming `.html` to `.php` without confirming host execution; Vite preview cannot verify the PHP include.

## Rollback
Before deployment, retain the last working ZIP and deployment directory backup. If tracking/form/order flow fails, restore prior working version and notify company owner; do not suppress errors or continue accepting potentially duplicate orders.
